OpenCode — агент в терминале

CLI-инструмент для AI

Работает прямо из консоли. Не нужен браузер, не нужна IDE.

Независимость от провайдера

Не привязан к одной модели. Можно подключать разные LLM.

Headless-режим

Работает в CI/CD без интерактивного терминала. Идеально для GitHub Actions.

OpenCode — мозг, PI — менеджер

OpenCode

Отвечает за интеллект агента. Генерирует код, анализирует контекст.

PI (Process Interface)

Харнес для автономного запуска. Управляет вводом/выводом без терминала.

В GitHub Actions нет интерактивного терминала. PI решает эту проблему.

workflow
┌─────────────────────────────────────┐
│ Prompt "проанализируй diff" │
│ ↓ │
│ PI → передаёт в OpenCode │
│ ↓ │
│ OpenCode → LLM анализирует │
│ ↓ │
│ → Repo / Tests / Commit │
└─────────────────────────────────────┘

Агент не угадывает — он идёт по шагам

01

Анализирует изменения в коде

Смотрит какие функции непокрыты тестами и какие файлы нужно дополнить.

02

Запускает coverage

Получает процент покрытия и список непокрытых функций.

03

Находит непокрытые функции

Идентифицирует auth.py, api.py — те, что нуждаются в тестах.

04

Пишет pytest-тесты

Генерирует файлы test_auth.py, test_api.py с проверяемыми сценариями.

05

Проверяет и сохраняет

Запускает pytest, убеждается что все тесты проходят, сохраняет тесты в проект.

// evaluation /первый_слой

def test_login_valid_user():

assert user is not None
assert user.role == "admin"
def test_login_wrong_password():
with pytest.raises(AuthError):
authenticate("admin", "wrong")

response = call_api("/health", timeout=1)
assert response.status == 200
✓ Хорошо покрывает

Базовые сценарии: happy path, ошибки ввода, таймауты.

Цель — не идеальность, а ускорение и снятие рутины.

ai-test-agent.yml
name: AI Test Agent
on: pull_request
jobs:
generate-tests:
runs-on: ubuntu-latest
steps:
- uses: actions/checkout@v4
- uses: actions/setup-python@v5
- run: pip install -r requirements.txt
- run: npm i -g opencode
- run: pi run opencode
env:
OPENCODE_API_KEY: ${{ secrets.OPENCODE_API_KEY }}
// secrets.perms /что_нужно

Что нужно для push от агента

OPENCODE_API_KEY

Добавить в GitHub Secrets. Без ключа агент не сможет обращаться к LLM.

Permissions

Настроить права на запись в ветку PR. Иначе коммит не пройдёт.

Contents: write

Разрешение на push изменений в ветку Pull Request.

settings
# GitHub Settings → Secrets
